# 在线编辑与发布

用户目标：在现有表单编辑器修改资料，直接保存到 GitHub 并更新 Pages，免下载上传。

实施选择（由实现者判断）：保留静态 Pages，通过 GitHub Contents API 提交固定仓库 main/content.js。使用仅授权此仓库 Contents 写入的 fine-grained token；不新增服务器。OAuth 一键登录需额外注册应用并维护认证服务，目前不引入。令牌由用户在编辑器输入，不在聊天中收集，仅存当前标签页内存；刷新需重新连接。

1. 添加可测试的 GitHub 客户端：UTF-8、固定 API 目标、认证、读取、带 SHA 的写入、冲突与网络失败处理。不保存令牌，不回显服务端敏感信息。
2. 在编辑器加入连接说明、保存并发布、加载远端和明确的冲突选择。草稿与基准一起保存，避免旧草稿在重新打开后覆盖较新的远端。保存过程中继续编辑的内容仍保持未发布。
3. 通过公开 content.js 的 Git blob SHA 检查实际上线内容，不把“提交成功”误报成“上线成功”。失败或超时保留草稿，允许重新检查。连接和部署状态分别显示。
4. 单元测试覆盖中文、无变化、并发冲突、权限、断网后重试、凭据隔离；浏览器检查桌面/移动布局和连接失败。独立审查后发布并核对线上资源。

验收：用户首次设置仓库级令牌后可直接发布；无须下载文件。不记录凭据；多人/多窗口更新不会静默覆盖；仍提供本地备份和手动发布作为备用。
